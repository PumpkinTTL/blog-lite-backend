# 第二轮代码清理与优化（R2）

> 日期：2026-06-23

> 触发：R1 修复 v2 接入后，发现会员码兑换链路仍有多个 P0 闭环漏洞 + 全项目存在一批状态机/错误处理/级联清理问题
> 方式：2 个 Explore agent 并行扫描（后端业务闭环 + 前端冗余代码）+ 人工核验 + 自测接口

## 为什么有第二轮

R1 聚焦"v2 客户端对接 API 的逻辑问题"，修了竞态、缓存泄漏、API 字段不匹配等。但深入测试会员码兑换时发现一整条业务闭环仍有严重漏洞：

- 捐赠发的会员码用户拿到后**无法兑换**（码被 disabled，兑换只接受 active）
- 终身会员兑换限时码后**被改成限时**（数据损坏）
- 跨等级兑换**无升降级策略**（产生多条并行记录）
- 同一用户可**刷满同一码**（无防刷）
- 错误提示直接暴露英文枚举值（"码状态为 used"）

进一步扫描还发现：删用户/删文章不级联清理、状态机不闭合（donation/resource toggleStatus）、错误细节泄露给用户、监听器泄漏等。这些是 R1 没覆盖的"功能闭环小细节"，本轮集中修复。

### 关键修复（按影响排序）

1. **捐赠答谢码无法兑换**（P0 致命）：新增 `assignedDonationId` 列解耦"池内可见性"和"可兑换性"
2. **终身会员被限时码覆盖**（P0 数据损坏）：grant 续期分支特判终身
3. **跨等级无处理**（P0 逻辑）：grant 实现升降级策略（升级作废低级 + 降级拒绝）+ 事务 + 悲观锁防并发
4. **降级时码被白白消耗**（P0 闭环）：redeem 流程加 preCheckGrant 预检查，消耗码前先校验
5. **删用户/删文章不级联**（P0 孤儿数据）：事务内清理 interactions/memberships/visibility + 回算计数
6. **错误提示暴露技术细节**（P1 文案）：codeStatusToMessage + IsEmail 中文 + email-code 错误脱敏

### 验证方式

- 后端：watch 模式热重启，TS 编译通过（修复了 issueLoginToken 返回类型错误）
- curl 测试：已确认"请先登录""请输入兑换码""资源不存在""文章不存在"等文案正确
- 前端：未跑构建（遵守"不构建"规则），改动都是删除/替换，类型安全有保障
